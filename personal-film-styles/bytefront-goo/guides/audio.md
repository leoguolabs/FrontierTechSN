# 旁白、电子配乐与拟音

### 英文

新制作的英文长片、短片使用 **OpenAI `gpt-realtime-2.1-mini` / Cedar**。工程的 `voice-config.json` 继承个人风格预设。按章连读，保留音高并按确认样音收紧开场与句间停顿。`npm run narrate:en` 生成章节 WAV 和来源回执。 [Cedar 配音、音量与同步](cedar-workflow.md)

保留原声和实际请求。以最终 48 kHz mono WAV 重新生成独立词位、字幕、画面、拟音和音乐，在播放器 1× 下验收。

台词显示稿与提交朗读稿分开保存。术语需要更改时，在段落的 `spoken_text` 填写完整朗读文本，字幕保留原文。听到误读后重录整个语义章，并在前后句的上下文中听审。

历史 Alloy 和 Tim 工程继续按其冻结配置重建。`--example clap-sync` 使用 `legacy-kokoro-eric` 配置和原始录音。 [Tim 历史制作流程](tim-workflow.md)

### 中文

使用火山引擎 **豆包语音合成 2.0 / 解说小明 2.0 男声**。提示语起点：“用明快、有精神的普通话男声讲科普，像把新发现讲给朋友听。语气有好奇和笑意，清晰、有起伏，但不喊叫。语速紧凑，句间自然短停，不拖长句尾；问题稍停后马上接答案。”附本期术语和读法，历史数学词表仅供该片。原官方体验页记录的三个控件值为 [0,10,0]；当前界面先核实标签和单位。保留实际参数、声线、提示词、原生下载与请求文稿。朗读稿中不混入提示语。

先按语义录一章，在前后句的上下文里听。官方来源若给 MP3，冻结原文件和哈希，用 PyAV 解码成 PCM16 mono；既有基准为 48 kHz，无改变时长。把本章实际提交的文本保存为 UTF-8，运行 `python scripts/import_zh.py CHAPTER take.wav --voice "解说小明 2.0" --speed 1.0 --request-text sent.txt`，速度填写实际倍数；原始界面值另存回执。zh 项目逐章重复。授权的服务执行环境或已登录官方界面可用时再生成新录音。

### 对齐与音乐

`python scripts/align_chapters.py` 可复用绑定 WAV 哈希的独立词位；首次生成词位在 Apple Silicon 的环境安装 requirements-review.txt，使用 mlx-whisper。其他平台可导入同字段的人工核实词位 JSON（sha256、text、words，每个 word 有 word/start/end 秒）。对齐时使用脚本原文出字幕，按真实时标切图。单段匹配率低或关键术语识别错误时，以录音定位检查；不要仅为过阈值替换旁白正文。改录音后缓存应失效。

配乐是现代极简电子：同一全片拍钟，铺底的和弦跨小节叠接、低音延伸、柔和序列、少量回声和一段可辨识的短动机。每个 `chapter.activity` 控制密度，`music.bpm/theme_midi/seed/motifs` 控制本期曲速、1–5 音动机、种子和落点。数学例为 92 BPM；新题材重写动机、落点和配器。机制中的六层是 cloud/underflow/current/halo/theme/beat，编辑 arrangement.json、MIDI 或各 stem 均可；要保留手工编曲请先另存工程并冻结导出的分轨。推导紧凑处抽掉打击或减少音符，让和声与混响自然过门。每章先用单个固定增益平衡到 −24 LUFS（人声总线增益前），保留章内表演和所有时间点；记录每章输入哈希、原响度及增益。不要以同一个全局增益掩盖章节音量差异。历史回放按原配置。背景初始约低于平衡后人声 18 LU，合成母带约 −16 LUFS，留约 1–2 dB 真峰值余量；按实际声音调整并测最终 AAC。少量拟音只对准可见的动作接触。

复查应同时播放一条连续 60–90 秒和每个章节交界，独听原声、音乐、拟音，再听总线。旧时间轴 0:23 的啸声、0:29 的突然加速、4:25 的 AI、5:43 的 ETH 是故障锚；重排版本用原短语定位。不要拿几个不相邻片段拼成一段去评判是否连续。
