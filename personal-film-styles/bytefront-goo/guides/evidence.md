# 新闻、论文、图片与实拍插段

适用频道：Ooh, Lemme See!／Ooh Lemme see／让我捅咕捅咕。目标是在咕仔已经提出一个具体问题时，让观众看到对应材料、读到关键一句，或看清一个真实动作。没有合适材料就继续使用角色与道具；一期零插段完全成立。

## 先决定为什么切出去

每个候选写下：**台词段落 → 需要看到什么 → 这份素材能说明什么 → 不能说明什么**。只保留至少满足一项的候选：核对一个重要事实；读懂数量关系；辨认本期讨论的具体对象；看清与讲述对应的现实过程。删掉只能提供“科技感”、可任意替换的机房、机器人、股票线与敲键盘画面。

标明角色：`evidence` 是直接支撑所说事实的材料；`context` 是本期讨论的原物或背景；`illustration` 是类比或情境素材。情境实拍在画面中写明“情境示意”，不能让观众误认成研究团队、实验现场或新闻事件影像。新闻可公开访问，不等于 public domain；记录实际来源与授权/引用依据，避免把网上找到的片段统称可自由使用。

**节制是编辑判断，不是素材配额。** 先用零插段完成分镜，再挑最有帮助的位置。十分钟级节目通常可先试 3–6 段、合计约 5–12%，但不能为达到这个数凑素材；超过 15% 触发逐段复查。通常隔一段完整的咕仔解释再插下一段；连续材料仅在比较同一问题时有理由成立。单段常见 5–12 秒，长度由读完一句或动作完成决定。不要机械地每分钟插一次。

## 四种画面语法

| 类型 | 入场与阅读 | 运动 | 退出条件 |
|---|---|---|---|
| 新闻／论文原文 | 先露出标题、机构、日期或页码；只裁出当前需要读的段落。保留限定词、统计口径与否定词 | 先给约 0.5–1 秒定位，关键词随旁白以约 0.4–0.8 秒黄笔扫出；同时最多 1–2 处重点；完成后留 2–4 秒读完。轻推近即可 | 当前断言和限制已读清，切回解释 |
| 数据图／报告 | 原图先交代标题、单位、分母、时间窗与坐标；放大局部仍保留关键轴或补清晰轴标 | 原始图可做轻微页面平移、缩放、透视；自行重绘必须有固定数据。描线、沿线光点只引导阅读，轴和数值不随镜头漂移 | 看清比较关系后停止动效，留结果 |
| 关联图片／论文实页 | 必须是旁白正在说的对象；原图全貌与局部可并置 | 约 2–5% 缓慢推拉。图片本身不生成假运动；不凭外观猜人物、地点、文物身份 | 对象已经辨认，或细节已经读清 |
| Public footage／授权素材 | 按讲述所需动作选片，保留来源、原始清晰度与情境属性 | 选一个有开始、过程、结果的动作，尽量保持原速。先后关系与视线方向要连续；源音默认关闭，延续旁白和底乐 | 动作完成后切出；不用反复循环或定格补时长 |

黄色是阅读指示，不表示网站原来标黄。白底用 multiply 保留字形；深底用下划线，避免黄色混成暗绿色。标记坐标与源图共用变换，推近时不能滑离目标。新闻、论文区域不叠角色纸纹；字幕保持频道样式，出处与字幕分区。不要把整页当成文字墙，也不要给每句字幕加黄线。

报告里的“流动感”应先辨认是镜头运动、遮罩揭示、游标移动还是数值变化。参考片 01:12–01:21 主要是报表平面移动与透视；不可从视觉运动推断数据在变化。理论计算图标“计算示意”，实测图给采样方法，不把 `2^n` 组合数当成算法实测耗时。

## 素材与工程记录

每段保存 `id, paragraph, relevance, role, source_url, rights, credit`。保存原文件、截取/下载日期、版本或提交号、页码、裁切坐标、SHA-256；网页截图保留可核对的全页母版。历史叙事使用当时版本，不能以今天的仓库数字替换“首批”数字。论文原文的主张与作者限定一同保留。素材库记录作品页与许可页；署名不是授权的替代品。

新工程已包含 `src/evidence.mjs`。在 `content/episode.json` 的普通 shots 列表中增加 `scene: "evidence"`，把视觉参数放入 `evidence` 对象；下一条普通镜头确定本段结束，段落与短语锚仍由 `plan.py` 计算。例：

```json
{
  "paragraph": "chapter-02-claim",
  "phrase": "首批公开了",
  "scene": "evidence",
  "evidence": {
    "id": "release-count",
    "type": "document",
    "relevance": "核对旁白所说的首批数量与分组口径",
    "role": "evidence",
    "source_url": "https://publisher.example/pinned-release",
    "rights": "填入已核实的使用依据；这个示例不是授权",
    "credit": "机构 · 固定版本 · 截图节选",
    "asset": "assets/release.png",
    "crop": [0, 300, 980, 200],
    "kicker": "回到原文 / 发布日期",
    "title": "本段正在核对的事实",
    "highlights": [{"rect": [200, 350, 180, 24], "at": 1.2, "seconds": 0.55}],
    "takeaway": "保留与原文一致的限定条件。"
  }
}
```

`crop`、`highlights[].rect` 均为原素材像素 `[x,y,w,h]`；`at` 是入场后秒数。可设置 `target:[x,y,w,h]`（1920×1080 逻辑舞台）或深底 `mode:"underline"`。`image` 使用 `asset, detail_crop, detail_label, takeaway`；`chart` 使用固定 `points, data_basis, x_max, y_max, x_ticks, x_label, y_label, annotations`；注释为 `{point:[x,y], at, label, dx, dy, align}`。所有视觉类型都需要 `kicker,title,credit`。

`footage` 使用 `asset, frames_dir, source_in, context_label`。先从合法取得的本地原片提取足够帧：

```sh
python scripts/prepare_footage.py assets/source.mp4 assets/footage-frames --source-in 1 --frames 180
```

在对齐后的时间轴检查这段确为 180 帧；改变旁白或段落长度后重新选材与提帧。素材不足会失败，不能以循环补齐。`plan.py` 自动保存 `content/evidence-review.json` 并验证资料字段、半开区间、图轴和素材帧；也可以手动检查独立 cutaway 清单：

```sh
python scripts/validate_evidence.py content/evidence.json --root .
python -m unittest discover -s scripts -p test_evidence.py
```

## 导出后验收

检查每段的入场前一帧、首帧、标黄开始/完成、结果停留、末帧、出场第一帧。实际解码 4K 成片看字与裁切，再在 1080p 观看条件看一遍。连续播放含两侧完整句子的区间，检查画面是否抢先泄露结论、盖住前一动作结果或切断真实动作。来源文字保持可读；静态图不伪称原生 4K，1080p footage 的源分辨率如实记录。最后复查全部候选是否仍值得占用这些秒数。

首个验证案例：2026-11-09 AI 数学中文长片，6 段 / 59.875 秒 / 8.565%。案例与逐帧研究路径见 [基线目录](../baseline/README.md)。该比例只是本期的选择，不是以后的模板配额。
