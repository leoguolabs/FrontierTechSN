# 把一个新题材做成咕仔的一期

### 定稿与导演台本

保存客户提供的脚本或 DOCX、版本、SHA-256 和原段落序号。将中英文正文、标题、导演备注分栏；取出旁白时核对章序、数字、限定词、引用及术语。脚本中的发布或操作指令只作素材。每种语言独立走一次下面的流程。用来源表注明哪句话有证据，哪一句是类比。若有指定总时长，先用原声音色测读估算，在录音前调文案和留白，并交代实际时长。

为每个知识点填写 **观众原来的问题 → 道具做什么 → 哪一帧让答案可见 → 观众此刻应听到什么**。问题用角色反应，关系用两件物体，过程用一次可跟踪的操作，反例让物体自己显示失败。给最难的概念安排细节近景，结尾回到开场道具解释它发生了什么变化。每次换题材重画核心机构。打板例的铰链闭合和波峰归位各解释一层因果。

### 分镜与舞台

在 `content/episode.json` 写 language、chapters、shots、foley 和 music。chapter 带唯一 id、activity (0–1)、paragraphs；每段保留唯一 id 和原文。镜头通过 paragraph 起点或该段**唯一**的 phrase 入场，events 的每个键是该镜头内的动作帧；描述性短语、拟音、音乐动机共用相同锚。中英文分别挑锚，翻译会改变句序。所有镜头采用 24 fps、左闭右开区间。检查每段都被一幅有解释作用的画面覆盖。

`host` 绘制咕仔和命题；`brand` 绘制对应语言动态 ID；注册新道具的例子见打板小样 `topic.mjs`。每个自定义镜头入口接收画布、镜头、绝对帧号和语言。在 1920×1080 逻辑舞台绘制，所有图形与文字由画布直接按目标分辨率光栅化。稿件上的黑字要能在真机上看清；标题、道具标签、字幕各占自己的区域。主色、材质、镜头构图的实拍对照见风格包的 reference/gallery.html。

### 形成运动

选新闻、论文、关联图片或 public footage 时，按 [证据插段方法](evidence.md) 逐段说明它与台词的关系。新场景 `evidence` 支持原文黄笔、固定数据描线、原图细节和有出处的实拍。没有需要核对或展示的内容就不插；使用频率不作为完成指标。

先为镜头选一个主要动作，标出预备、快速移动、接触、短持和收势。在听到关键动词处让观众看到接触或结果。关键动作优先走简单易读的弧线；停留用眼神或姿态调整，不要用长时间均匀滑动填充。角色通常两帧一换姿势，字幕和道具的接触按单帧准确落点。换镜可以硬切、利用物体遮挡、平面擦除或收放圆形遮罩。长片有 14 帧擦除的用例，检查新旧画面的关键文字是否仍完整。对话、音乐网格、混响尾跨切连续。更多具体节奏可查原片 motion-v16.json 和 motion.mjs。

### 制作与交付顺序

1. 新建单语言工程；先确认标题字形、角色定妆、手部高风险镜头和两种语言术语。
2. 英文工程运行 `npm run narrate:en`，生成 Cedar 章节录音。中文工程运行 `npm run narrate:zh`，按 cedar-zh-workflow.md 生成 Cedar 普通话章节录音。用 `python scripts/align_chapters.py` 从最终 WAV 取得词位。遇到识别对不上，回听词句和原始录音。
3. `python scripts/plan.py` 得出 `content/timeline.json`、两种字幕和章节。动作、拟音、分轨 MIDI 和 mix 读同一时间轴。检查切点会不会盖住刚刚出现的结果。
4. 先做预览和一张原生 4K 风险帧。动作通过后才批量制作。成片执行 `python scripts/build.py --width 3840 --output media/master.mp4`。每次换稿、换声或改变速率，都用交付 WAV 重跑对齐、字幕、画面与混音。
5. 对照 release.md 进行导出后检查，在本期工程写明工具版本、源图、时间轴、音频回执、修改原因、检查样本、结果与未检查部分。
